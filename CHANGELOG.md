## Что нового в версии 2.0.4

### Карты превращения

Добавлен отдельный каталог карт превращения. В карточках отображаются характеристики формы, скорость, длительность, подтверждённые постоянные эффекты и навыки формы.

Для превращений доступны поиск, сортировка и фильтрация по характеристикам. Добавлен фильтр **«Цель — союзник»**, а сами превращения можно сохранять в общее «Избранное» без нарушения совместимости существующих профилей.

Превью навыков стало точнее: отдельно учитываются баффы, дебаффы и мгновенные полезные действия. Лечение, исцеление, очищение и снятие отрицательных эффектов больше не теряются только из-за отсутствия длительности эффекта.

### Усиление предметов

Для поддерживаемой экипировки добавлен просмотр усиления от **«Без усиления»** до **+10** по исходным данным `item_enhanced.txt`. Бонус усиления показывается рядом с базовой характеристикой в скобках, без подмены исходного значения предмета.

Выбор усиления перенесён в компактный элемент перед названием предмета. Исправлено отображение двузначного уровня усиления: значение **+10** полностью помещается в элементе управления, в том числе на узких экранах.

### Карточки и интерфейс

Карточки очищены от пустых секций и технического шума. Блоки без фактических данных больше не показывают заголовки, заглушки вида «Нет данных» и пустые строки. Это относится в том числе к эффектам и навыкам превращений, титулам, рецептам и общим характеристикам.

В карточках предметов восстановлено поле **«Используемое умение»** там, где оно подтверждается исходными данными. Вес, используемое умение и ранг расположены в едином игровом порядке; количество печатей подписано явно. Источники получения относятся к базовому предмету без усиления.

Исправлено отображение недавно просмотренных записей, уточнены подписи и состояния интерфейса, обновлены цвета агрессивных и дружелюбных монстров. Интерфейс повторно проверен для мобильных ширин 320 и 380 px.

### Классификация оружия

Полностью перепроверена классификация раздела **«Оружие/щит»** по исходному полю типа оружия, а не по названию предмета или косвенным признакам.

Проверены **1831 запись** раздела, включая один технический инструмент. Для **424 предметов** исправлено пользовательское представление типа. В частности, устранены системные ошибки между мечами, двуручными мечами, саблями, кинжалами, ружьями, посохами, скипетрами и щитами.

Категория **«Парные клинки»** больше не используется как самостоятельный тип оружия там, где исходный игровой тип соответствует саблям. Исправление применяется единообразно в карточках, каталогах, фильтрах, поиске и результатах рецептов.

### Источники и данные

Мировая добыча больше не показывается как собственная добыча конкретного монстра. Правило мировой добычи остаётся доступно на карточке предмета без создания ложной связи с отдельным монстром.

Исправлена обработка рецептов, которые ссылаются на отсутствующие в опубликованной базе материалы: такие строки больше не блокируют загрузку и не ведут на несуществующую карточку.

Усилены проверки различий между **The Original** и **Iris Kiss Kiss**. Приложение не подставляет данные одного сервера вместо отсутствующих данных другого.

### Последняя запись ВКонтакте

Проверка сохранённой записи стала устойчивее к недоступности одного GitHub-источника: используется резервное чтение через GitHub API, а интерфейс больше не называет любую ошибку загрузки отсутствием сети.

Исправлен сам сборщик последней записи ВКонтакте: он проверяет все поддерживаемые публичные варианты стены (`vk.ru`, `vk.com` и мобильную версию) и выбирает запись с максимальным подтверждённым ID вместо остановки на первом найденном, но потенциально устаревшем варианте.

Ручная проверка больше не сообщает **«Последняя запись ВКонтакте обновлена»**, если ID записи фактически не изменился. В этом случае показывается точный статус **«Новых записей ВКонтакте нет.»**

### Надёжность и выпуск

Добавлены регрессионные проверки карт превращения, усиления, пустых секций, типов оружия и обновления записи ВКонтакте.

PREPARE RELEASE автоматически исправляет безопасные проблемы форматирования и Ruff lint, затем повторно проверяет уже обновлённый release-коммит. Получение `origin/main` использует безопасный `--refetch`, чтобы тонкая локальная Git-история восстанавливалась перед VCS-проверками.

Release fingerprint связывает проверенное состояние исходников с конкретным HEAD и повторно проверяется перед публикацией commit и GitHub Release.

## Что нового в версии 2.0.3

### Титулы

Титулы стали полноценными записями базы: их можно открывать как предметы и монстров. В карточке отображаются уровень, эффект и подтверждённые источники получения.

Добавлены сортировка по уровню, названию и индексу, фильтр по диапазону уровней и чекбокс **«Известно, где получить»**.

Индекс титула отображается компактным числовым префиксом без служебной подписи. В карточке добавлены технические сведения с индексом титула и ID связанных игровых предметов.

Для категорий предметов восстановлено исходное цветовое различие: покупные предметы используют `#ffcd00`, ивентовые — `#c9a0dc`.

### Награды заданий

Для **56 титулов** и **19 рецептов** добавлены подтверждённые источники из наград за выполнение заданий. Для титулов исходные файлы содержат 62 связи с заданиями: несколько разных заданий могут выдавать один и тот же титул.

В источнике отображаются название и ID задания, а также тип награды. Награды берутся из общих игровых ресурсов; доступность самого задания на The Original или Iris Kiss Kiss отдельно не утверждается.

### Устранение дублей

Титульные знаки исключены из каталога предметов и глобального поиска по предметам. Раздел **«Расходники → Титул»** больше не дублирует отдельный каталог титулов.

Несколько технических предметов, относящихся к одному титулу, объединяются в одну запись без потери подтверждённых источников получения. Старые ссылки и записи избранного на титульные предметы переводятся на соответствующий титул.

### Интерфейс

Исправлено отображение карточки титула: длинные названия больше не сжимаются в узкую колонку и корректно переносятся на узких экранах.

Убрано повторение названия рядом с кнопкой «Назад» в карточках. Кнопка «Назад» стала заметнее, а размер префикса индекса титула выровнен по высоте заглавной буквы.

Уточнено описание серверных данных: приложение больше не утверждает, что характеристики предметов на The Original и Iris Kiss Kiss обязательно совпадают. Подпись сброса фильтров приведена к единому виду.

### Надёжность

Добавлены регрессионные проверки каталога титулов, уровней, источников получения, дедупликации, поиска, старых ссылок и избранного.

Исправлена совместимость release-скрипта с Windows PowerShell 5.1 на системах с не-UTF-8 кодовой страницей. `CHANGELOG.md` при публикации теперь читается явно как UTF-8, чтобы русский текст GitHub Release не искажался.

## 2.0.1 — 2026-08-19

- Рецепты исключены из каталога «Предметы» и результатов глобального поиска по предметам; старые ссылки `#item/<id>` на рецепты переводятся в раздел «Рецепты».

- Повторная проверка одного и того же VK-поста не создаёт новый commit только из-за косметических различий текста, emoji или разметки.
- Локальный Windows release-gate снова запускает Python regression-тесты из актуального каталога `tests/`, а не из прежнего `tools/`.

### Changed

- Главная страница стала короче: удалены жёстко заданные счётчики монстров и повторяющиеся пояснения о серверах.
- Убрана принудительная плавная прокрутка; форматтеры чисел и дат переиспользуются вместо повторного создания.
- Python regression-тесты вынесены из `tools/` в отдельный каталог `tests/`; CI запрещает возвращение `tools/test_*.py`.
- Scheduled VK workflow использует системный Chrome/Chromium GitHub Runner вместо повторной тяжёлой установки браузера.
- Для изменений VK updater добавлена live-проверка после push в `main` без рекурсивного запуска от bot-коммитов данных.

### Build/CI

- Усилен контракт согласованности версии: `VERSION`, web UI, README, Wails metadata и Windows PE metadata должны указывать одну версию.
- Release-gate синхронизирован с текущей структурой тестов и Bandit-проверок.
- Сохранены строгие проверки Go 1.26.6, Staticcheck, govulncheck, Ruff, Bandit, pip-audit, frontend smoke, Gitleaks current/history, CodeQL, dependency review и Windows-сборки x64/x86/ARM64.

## 2.0.0 — 2026-08-13

### Added

- Нативное Windows-окно на Wails 2.14.0 и Microsoft WebView2 с системной иконкой, Alt+Tab, панелью задач, сворачиванием, разворачиванием и нормальным закрытием.
- Single-instance lifecycle: второй запуск активирует уже открытое окно.
- Строгий allowlist внешних HTTPS-ссылок и системное открытие вне WebView.
- Проверка Windows PE metadata, DPI manifest и hardening-флагов.
- Детерминированные VK fixtures и frontend smoke на нескольких DPI-scale factors.

### Changed

- Внешняя браузерная вкладка и UI-сервер на `127.0.0.1:8765` заменены embedded asset handler и внутренним Go/JavaScript transport Wails без TCP-listener.
- Проект использует один канонический Git/source tree для теста, сборки и публикации.
- Release pipeline собирает и проверяет три Windows-архитектуры: x64 (`amd64`), x86 (`386`) и ARM64 (`arm64`); `SHA256SUMS.txt` содержит хэши всех трёх EXE.
- Блок «Предметы с наибольшим шансом» показывает компактные строки `название — процент`, не меняя математику выпадения.
- Release-скрипты сгруппированы в `scripts/`, а артефакты всегда создаются вне source tree.

### Fixed

- Исправлена Windows-проверка инструментов: native output больше не обрывается до завершения процесса, корректно распознаётся вывод `staticcheck.exe`, а Python packages проверяются в том же внешнем audit venv, куда были установлены.
- `Check` и `Install` автоматически запрашивают права администратора через UAC и повторно загружают `PATH` после winget без обязательного перезапуска терминала.
- VK updater больше не заменяет last-known-good новость пустым текстом или записью с меньшим ID.
- Восстановлено корректное превью записи №62337 из проверенной истории репозитория вместо пустого состояния №62336.
- Добавлены DOM/OpenGraph fallback, ограниченные retry/timeout и безопасная диагностика `ERR_ABORTED`/timeout.
- VK updater декодирует HTTP body по объявленному charset и с безопасным Windows-1251 fallback; не-UTF-8 ответ VK больше не роняет scheduled workflow через `UnicodeDecodeError`.
- Принудительное обновление VK больше не очищает видимое последнее корректное превью при временной сетевой ошибке.
- Repository audit и его regression-тест используют единый redacted contract с категориями и точным количеством нарушений.
- Python shebang/executable mode приведены в соответствие с Ruff EXE001.

### Security

- CSP запрещает remote scripts, frames, objects и произвольные сетевые запросы WebView.
- Remote VK text всегда проходит escaping; внешняя навигация не получает доступ к Wails bindings.
- Audit/CodeQL paths не печатают raw failure payload, токены или пользовательские абсолютные пути.
- GitHub Actions имеют минимальные permissions и полные commit SHA; write permission оставлена только VK job.
- Gitleaks проверяет текущий source и полную Git history из официального бинарника с SHA-256.

### Build/CI

- Добавлены Linux quality/security, Go race и native Windows Wails build jobs.
- RELEASE fingerprint связывает source SHA-256, HEAD, branch, версии инструментов и конфигурацию.
- Все прямые Python audit/smoke-зависимости, включая Ruff, Bandit, pip-audit, Playwright и PyYAML, закреплены только в `tools/requirements-audit.txt`.
- pip-audit использует переиспользуемое окружение вне source и проверяет полное установленное dependency graph.
- Потенциально зависающие security/build/browser checks имеют watchdog и не превращают infrastructure failure в PASS.
- Windows `govulncheck` повторяет канонический запрос и переключается на Google-hosted storage endpoint той же Go Vulnerability Database; недоступность обоих адресов оставляет security status `UNKNOWN` и блокирует RELEASE fingerprint.
- Windows-wrapper считывает фактический exit code `govulncheck` через `System.Diagnostics.Process`; успешный ответ `No vulnerabilities found.` больше не классифицируется как `SECURITY FAIL`; паузы retry сокращены до 2 с.
- Вывод Windows-инструментов захватывается прямым процессом без PowerShell Job/remoting и декодируется как UTF-8; диагностический `RemoteException` и повреждение кириллицы в VK fixture output устранены.
- Windows `SelfTest` проверяет UTF-8 по детерминированной последовательности байтов штатным Windows PowerShell и при сбое сообщает безопасную категорию конкретного probe вместо одного непрозрачного счётчика.
- Совместимый `01_TEST.bat` для привычного запуска строгого PowerShell RELEASE gate вынесен из source archive в отдельный артефакт; launcher делегирует текущему `IrisTools.ps1 -Action Test` и не дублирует логику проверок.
- Windows release build теперь явно фиксирует `CGO_ENABLED=0`; проверка Go metadata сообщает безопасную категорию несовпадения вместо непрозрачного общего сообщения.
- Кнопка «Назад» в карточке использует ограниченную внутреннюю историю: переход из шкатулки в руну возвращается в исходную шкатулку, а прямой deep link безопасно откатывается к каталогу.
- Repository audit проверяет executable mode Python-файлов по Git index, поэтому EXE001 regression одинаково работает на Windows и Linux; Windows runner сохраняет redacted traceback провалившегося tool вместо одной строки progress output.

Исторические изменения выпусков 1.x доступны в Git history и соответствующих тегах.
