# Iris Online Database

Локальная база данных для Iris Online. Приложение работает на компьютере пользователя, открывается в браузере и использует игровые данные, встроенные в пакет.

Официальный сайт Iris Online: `https://irisonline.ru/`.

## Возможности

- поиск по предметам и монстрам;
- каталоги с фильтрами, сортировкой и серверной пагинацией;
- карточки предметов с характеристиками, требованиями, слотами карт, комплектами и источниками получения;
- все подтверждённые эффекты комплектов, включая пороги 2, 3, 4 и 5 предметов;
- карточки монстров с доступными характеристиками и добычей;
- корректное представление monster-specific, world и quest drop без выдачи runtime-зависимой вероятности за точный шанс получить предмет за убийство;
- избранное и недавно просмотренные предметы/монстры;
- локальный пользовательский профиль: сервер, тема, вид, фильтры, избранное и история;
- светлая и тёмная темы;
- встроенные ресурсы Iris Online и ссылки на сообщества.

Раздел с привязкой монстров и NPC к конкретным подземельям не показывается: в доступных исходных данных нет надёжной таблицы `entity → map` для такой связи.

## Запуск

Готовая сборка запускает локальный HTTP-сервер только на loopback-интерфейсе и открывает приложение в системном браузере.

Из исходников:

```bash
go run .
```

Без автоматического открытия браузера:

```bash
go run . -no-browser
```

По умолчанию используется `127.0.0.1:8765`. Параметр `-addr` принимает только loopback-адрес.

## Поддерживаемые Windows-архитектуры

Скрипты сборки создают варианты для:

- Windows x64;
- Windows x86;
- Windows ARM64.

Целевая версия Go указана в `.go-version`. Обычная публикационная сборка разрешена только при точном совпадении toolchain с этим файлом. Windows-иконка и manifest входят в исходное дерево как воспроизводимые ресурсы для x64, x86 и ARM64.

## Поиск и работа с базой

Основной поиск принимает названия и ID. Результаты ведут непосредственно к предметам и монстрам. Каталоги поддерживают фильтры и сортировку, а большие наборы данных выдаются серверными страницами.

Для выпадения приложение различает вес группы, базовый шанс выбора предмета и базовый шанс за одну попытку. Фактический шанс получить предмет за убийство может зависеть от уровня, дополнительных попыток, временных ограничений и других серверных условий, поэтому недоказанная итоговая вероятность не показывается как точная.

Игровые названия, характеристики, классы, эффекты, валюты и цвета редкости сохраняются из исходных данных без литературной переработки.

## Профиль

Профиль хранится локально. В нём сохраняются:

- выбранный сервер;
- тема и вид;
- фильтры;
- избранное;
- история поиска;
- недавно просмотренные предметы и монстры.

Формат профиля остаётся совместимым с ранее созданными профилями схемы v1. При повреждении основного JSON приложение может использовать корректную резервную копию. Безопасные неизвестные поля верхнего уровня не удаляются при обычном чтении и сохранении.

## Сборка из исходников

Требуемая версия Go указана в `.go-version`.

Windows PowerShell 5.1+:

```powershell
.\build.ps1
```

`build.ps1` сам включает CGO только на время `go test -race`, проверяет доступность C-компилятора и затем собирает Windows EXE с `CGO_ENABLED=0`. Переменные окружения процесса восстанавливаются после завершения. Для race-проверки нужен GCC или другой компилятор, указанный через `CC`.

Bash:

```bash
./build.sh
```

При требуемом toolchain создаются EXE с marker:

```text
IrisOnlineRelease/1.0
```

и именами:

```text
IrisOnlineDB-1.0-Windows-x64.exe
IrisOnlineDB-1.0-Windows-x86.exe
IrisOnlineDB-1.0-Windows-arm64.exe
```

Сборка другим Go блокируется. Для локальной диагностики её можно явно разрешить через `IRIS_ALLOW_UNSUPPORTED_GO=1`; такая сборка получает отдельный marker `IrisOnlineDiagnostic/1.0/<go-version>` и диагностические имена файлов. Она не предназначена для публикации как официальный build приложения.

## Проверки

Основной набор:

```bash
go test -count=1 ./...
go test -race -count=1 ./...
go vet ./...
node --check web/app.js
python3 -m unittest discover -s tools -p "test_*.py"
```

Дополнительно в `tools/` находятся bounded smoke/regression-проверки API, UI, lifecycle, памяти, полноты данных и серверной модели выпадения. Актуальные результаты и SHA-256 встроенных игровых assets приведены в `TEST_REPORT.md`.

## Данные и сеть

Игровые данные, JavaScript и CSS встроены локально. Приложение не загружает удалённые скрипты, шрифты или изображения и не отправляет телеметрию. Внешняя сеть используется только после явного перехода пользователя по ссылке.
