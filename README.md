# Iris Online Database 1.1.0

Локальное приложение для просмотра встроенной базы данных Iris Online. Программа запускает HTTP-сервер только на локальном адресе `127.0.0.1` и открывает интерфейс в системном браузере.

Автор программы: **Хоуп (Original)**.

Официальный сайт игры: `https://irisonline.ru/`.

GitHub проекта: `https://github.com/fsibatov/iris-online-database`.

## Что нового в 1.1.0

Версия 1.1.0 — новый минорный выпуск с отдельным разделом рецептов и накопленными улучшениями интерфейса. Основные изменения:

- добавлен отдельный раздел «Рецепты»;
- для рецептов доступны поиск, фильтры, сортировка по уровню мастерства и отображение материалов;
- в карточке рецепта показывается готовый предмет и его подтверждённый эффект, если связь можно определить однозначно;
- для предметов и рецептов доступен фильтр «Известно, где получить»;
- улучшены сортировка каталогов, пагинация и порядок фильтров;
- исправлено поведение приложения при переводе вкладки Microsoft Edge в фон и при перезагрузке страницы;
- фильтры каталогов сбрасываются при новом запуске приложения;
- полностью вычитаны русские тексты интерфейса, сообщений и сопроводительных файлов;
- игровые данные не изменялись.

## Готовая версия

Выберите файл, соответствующий архитектуре Windows:

- `IrisOnlineDB-1.1.0-Windows-x64.exe` — для большинства компьютеров с 64-разрядной Windows;
- `IrisOnlineDB-1.1.0-Windows-x86.exe` — для 32-разрядной Windows;
- `IrisOnlineDB-1.1.0-Windows-arm64.exe` — для Windows on ARM.

Сборка для публикации версии 1.1.0 должна выполняться Go 1.26.5, указанным в `.go-version`.

По умолчанию приложение использует локальный адрес `127.0.0.1:8765`. Подключения извне не принимаются.

## Возможности интерфейса

- каталог предметов;
- каталог монстров;
- отдельный каталог рецептов;
- глобальный поиск по названию и ID;
- фильтры и сортировка каталогов;
- фильтр «Известно, где получить» для предметов и рецептов;
- подробные карточки предметов, монстров и рецептов;
- характеристики предметов и монстров;
- комплекты и их эффекты;
- материалы рецептов и требуемый уровень мастерства;
- готовый предмет рецепта и его эффект, если данные позволяют определить их однозначно;
- источники получения: выпадение с монстров, мировая добыча, сундуки и задания;
- содержимое сундуков и подтверждённый шанс получения предмета при открытии;
- избранное;
- недавно просмотренные предметы и монстры;
- переключение между данными серверов Original и Kiss;
- светлая и тёмная темы.

Игровые данные встроены в приложение и не загружаются из внешних источников. При запуске приложение может один раз обратиться к публичному GitHub API, чтобы проверить наличие более новой опубликованной версии. Обновления не скачиваются и не устанавливаются автоматически.

## Original и Kiss

Original и Kiss — два сервера Iris Online. Предметы и их характеристики в текущей базе общие, но состав монстров и некоторые способы получения предметов могут различаться.

После выбора сервера приложение учитывает его данные в каталоге монстров, поиске и источниках получения. В текущем пакете указано:

- Original — 609 монстров;
- Kiss — 677 монстров.

Отсутствие монстра в предоставленном списке размещения не доказывает, что он никогда не может появиться через отдельный сценарий, событие или умение. Поэтому общая таблица монстров не изменяется: серверная доступность хранится отдельно.

## Рецепты

В текущем пакете содержится **1 207 рецептов** и **4 129 связей с материалами**.

Каталог рецептов поддерживает:

- поиск по названию и ID рецепта;
- поиск по названию материала;
- фильтр по типу рецепта;
- фильтр по редкости;
- диапазон требуемого уровня мастерства;
- фильтр «Известно, где получить»;
- сортировку по названию, уровню мастерства и редкости.

Уровень мастерства — это число в скобках после профессии. Например, `Каллиграф (20)` означает требуемый уровень мастерства 20.

Если источник рецепта известен, приложение показывает его с учётом выбранного сервера. Если источник один, он выводится один раз без дублирования. Если источников несколько, доступен полный список.

Если готовый предмет рецепта можно однозначно сопоставить с предметом в базе, карточка рецепта показывает ссылку на него и подтверждённый эффект или характеристики. При неоднозначном соответствии приложение ничего не угадывает.

## Источники получения

Источники группируются в следующем порядке:

1. монстры с подтверждённым выпадением;
2. мировая добыча;
3. сундуки;
4. задания;
5. другие известные источники.

Для обычного выпадения с монстров интерфейс показывает подтверждаемые составляющие расчёта: шанс группы, шанс предмета внутри выбранной группы и шанс за одну основную попытку.

Для мировой добычи известны условия по уровню и типу монстра. В предоставленных данных нет надёжной связи каждого монстра с конкретной открытой локацией или инстансом, поэтому приложение не выдаёт подходящий список за подтверждение конкретной карты.

## Сундуки

Содержимое сундуков хранится во встроенном файле `assets/chest_contents.json.gz`. В текущих данных содержится 399 профилей сундуков и 4 944 строки предметов для каждого сервера.

Процент показывается только тогда, когда его можно подтвердить по имеющимся данным. Если модель конкретного профиля неоднозначна, содержимое остаётся доступным, но неподтверждённый процент не выводится.

## Пользовательские данные

Настройки, избранное, история поиска и недавно просмотренные записи сохраняются локально на компьютере пользователя.

Профиль записывается атомарно с резервной копией. Версия 1.1.0 продолжает использовать схему профиля v1 и сохраняет совместимость с ранее созданными профилями этой схемы.

Фильтры каталогов считаются временными: при новом запуске приложения они сбрасываются.

## Проверка обновлений

Iris Online Database обращается только к публичному GitHub API репозитория `fsibatov/iris-online-database`, чтобы узнать номер последнего опубликованного релиза.

Запрос выполняется не более одного раза за процесс и не содержит профиль пользователя, историю, избранное, поисковые запросы или игровые данные. При отсутствии доступа к интернету локальная база продолжает работать. Если найдена новая версия, приложение показывает только ссылку на страницу релиза GitHub.

## Требуемая версия Go

Версия Go для сборки, предназначенной для публикации, зафиксирована в `.go-version`:

```text
1.26.5
```

`build.ps1` и `build.sh` проверяют установленную версию Go перед сборкой.

Переменная

```text
IRIS_ALLOW_UNSUPPORTED_GO=1
```

разрешает диагностическую сборку другой версией Go. Такая сборка получает диагностический маркер и не должна выдаваться за официальный релиз.

Windows EXE собираются с `CGO_ENABLED=0`.

Архитектуры:

```text
x64:   GOARCH=amd64, GOAMD64=v1
x86:   GOARCH=386, GO386=softfloat
ARM64: GOARCH=arm64, GOARM64=v8.0
```

## Запуск из исходного кода

Обычный запуск:

```bash
go run .
```

Запуск без автоматического открытия браузера:

```bash
go run . -no-browser
```

Основные параметры:

```text
-addr 127.0.0.1:8765
-no-browser
-shutdown-when-idle
-idle-grace 6s
-heartbeat-timeout 90s
-startup-timeout 55s
```

Приложение может прослушивать только локальные адреса обратной петли (`loopback`).

## Проверки

В Linux, macOS или другой среде с Bash:

```bash
bash ./tools/run_all_checks.sh
```

Основные проверки можно запускать отдельно:

```bash
go test -count=1 ./...
go test -race -count=1 ./...
go vet ./...
node --check web/app.js
python3 -m unittest discover -s tools -p "test_*.py"
```

Для `go test -race` требуется поддерживаемый C-компилятор и включённый CGO.

Дополнительные интеграционные проверки находятся в каталоге `tools/`.

## Сборка

### Windows PowerShell

```powershell
.\build.ps1
```

Для проверки `go test -race` в Windows должен быть доступен GCC или другой совместимый C-компилятор.

Готовые Windows EXE создаются в каталоге `dist`.

### Linux и macOS

```bash
bash ./build.sh
```

`build.sh` рекомендуется запускать именно через Bash, поэтому исполняемый бит файла после распаковки архива не требуется.

## Исходный архив

Каталог `dist` содержит результаты сборки и не должен входить в архив исходного кода.

Также в архив исходников не следует включать:

```text
__pycache__/
*.pyc
*.exe
```

Готовые Windows EXE и файл контрольных сумм распространяются отдельно.

## Безопасность локального приложения

- HTTP-сервер принимает подключения только с локальных адресов;
- проверяются заголовки `Host` и `Origin`;
- межсайтовые API-запросы отклоняются;
- используются защитные HTTP-заголовки и Content Security Policy;
- интерфейс не требует удалённых JavaScript, CSS, шрифтов или изображений;
- телеметрия отсутствует;
- игровые данные не загружаются удалённо;
- проверка версии не передаёт пользовательский профиль или поисковые данные;
- размер запросов и число одновременных запросов ограничены;
- пути пользовательских данных проверяются перед чтением и записью;
- кэш ответов, сессии, профиль и история имеют ограниченный размер;
- приложение поддерживает штатное завершение локального сервера.

## Структура проекта

- `server.go` — запуск приложения, локальный HTTP-сервер и промежуточные обработчики;
- `main.go` — игровые модели, загрузка данных, поиск и API;
- `lifecycle.go` — браузерные сессии и завершение приложения;
- `storage.go` — пользовательский профиль, резервные копии и очистка;
- `cache.go` — ограниченный кэш HTTP-ответов;
- `web/` — локальные HTML, CSS и JavaScript;
- `assets/` — встроенные игровые данные;
- `resources/` — манифест Windows и значок приложения;
- `tools/` — проверки и вспомогательные инструменты.
