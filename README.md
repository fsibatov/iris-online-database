# Iris Online 1.0.1

Локальное приложение для просмотра встроенной базы данных Iris Online. Исполняемый файл запускает HTTP-сервер только на loopback-адресе и открывает интерфейс в системном браузере.

Автор программы: **Хоуп (Original)**.

Официальный сайт игры: `https://irisonline.ru/`.

GitHub проекта: `https://github.com/fsibatov/iris-online-database`.

## Готовая версия

Выберите файл для архитектуры Windows:

- `IrisOnlineDB-1.0.1-Windows-x64.exe` — большинство компьютеров с Windows;
- `IrisOnlineDB-1.0.1-Windows-x86.exe` — 32-разрядная Windows;
- `IrisOnlineDB-1.0.1-Windows-arm64.exe` — Windows on ARM.

Официальные релизные EXE версии 1.0.1 собираются Go 1.26.5.

По умолчанию приложение использует локальный адрес `127.0.0.1:8765`. Внешние подключения не принимаются.

## Интерфейс

Основные возможности:

- каталог предметов;
- каталог монстров;
- поиск по названию и ID;
- фильтры;
- подробные страницы предметов и монстров;
- информация о комплектах;
- источники получения и выпадения: точные монстры, мировая добыча, сундуки и квестовые источники;
- содержимое сундуков и расчёт шанса получить предмет при открытии;
- ленивое раскрытие подходящих монстров для мирового дропа;
- избранное;
- недавно просмотренные предметы и монстры;
- переключение доступных наборов данных;
- светлая и тёмная тема.

Игровые данные встроены в приложение и не загружаются из внешних источников во время обычной работы.

## Источники получения и сундуки

Источники предмета выводятся в порядке: точные монстры, мировая добыча, сундуки, квестовые источники. Точные монстры сортируются по базовому шансу по убыванию, затем по уровню по возрастанию и по названию.

Для мирового дропа интерфейс показывает подходящих монстров по подтверждённым условиям уровня и типа. В доступных данных нет доказанной связи конкретного монстра с условием карты `field/instance`, поэтому интерфейс не выдаёт такой список за точную привязку к локации.

Карточка монстра также содержит отдельный ленивый раздел «Мировая добыча». Он показывает те же мировые правила, которым монстр подходит по уровню и типу, и явно отделяет это от подтверждённой обычной добычи. Поэтому предметы мирового дропа не теряются при просмотре источника со стороны монстра.

Содержимое сундуков и других подтверждённых контейнеров хранится в `assets/chest_contents.json.gz` — компактной проекции исходных `item_change.txt` для Kiss/Original. Сырые server tables в распространяемый source tree не входят. Контейнер определяется не по одной каталожной категории, а по согласованным признакам исходной проекции предмета: `kindOf=3`, `eventType=3`, `changeIndex=<ID предмета>`. Поэтому сохраняются также ящики/шкатулки из категории квестовых наград. В текущих данных это 399 профилей и 4 944 предметные строки на каждый сервер.

Модель сохраняет `rate`, исходный порядок строк, `item`, `count`, `enhanced` и `changerate`. Для профилей, где `changerate` укладывается в подтверждаемую накопительную шкалу `1..1 000 000`, одинаковые пороги рассматриваются как одна группа наград, а вероятность группы определяется разницей соседних порогов. Если контейнер выбирает несколько наград, шанс предмета рассчитывается как вероятность получить его хотя бы один раз. У профиля `873079` исходные значения `changerate` выходят за шкалу 1 000 000, поэтому его содержимое сохраняется, но процент в интерфейсе намеренно не показывается. Это поведение подтверждается структурой таблиц и игровыми описаниями контейнеров; отдельного server implementation кода `item_change` в предоставленных reference-файлах нет.

## Пользовательские данные

Настройки, избранное и история сохраняются локально на компьютере пользователя.

Запись профиля выполняется атомарно с резервной копией. Формат профиля версии 1 сохраняет совместимость с предыдущими поддерживаемыми версиями приложения.

## Toolchain

Целевой и обязательный toolchain официального релиза зафиксирован в `.go-version`:

```text
Go 1.26.5
```

`build.ps1` и `build.sh` проверяют версию Go перед сборкой.

Переменная:

```text
IRIS_ALLOW_UNSUPPORTED_GO=1
```

предназначена только для диагностической сборки другим toolchain. Такая сборка не должна распространяться как официальный релиз.

Финальные Windows EXE собираются с:

```text
CGO_ENABLED=0
```

Параметры архитектур:

```text
x64:   GOARCH=amd64, GOAMD64=v1
x86:   GOARCH=386, GO386=softfloat
ARM64: GOARCH=arm64, GOARM64=v8.0
```

## Запуск из исходного кода

Обычный запуск:

```bash
go run .
```

Без автоматического открытия браузера:

```bash
go run . -no-browser
```

Основные параметры:

```text
-addr 127.0.0.1:8765
-no-browser
-shutdown-when-idle
-idle-grace 6s
-heartbeat-timeout 90s
-startup-timeout 55s
```

Адрес прослушивания ограничен loopback-интерфейсами.

## Проверки

Linux/macOS или другая среда с Bash:

```bash
bash ./tools/run_all_checks.sh
```

Базовые проверки можно запускать отдельно:

```bash
go test -count=1 ./...
go test -race -count=1 ./...
go vet ./...
node --check web/app.js
python3 -m unittest discover -s tools -p "test_*.py"
```

Для `go test -race` требуется поддерживаемый C-компилятор и включённый CGO.

Дополнительные smoke-тесты находятся в каталоге `tools/`.

## Сборка

### Windows PowerShell

```powershell
.\build.ps1
```

Для race-проверки в Windows должен быть доступен GCC или другой совместимый C-компилятор.

Официальные Windows EXE создаются в каталоге `dist`.

### Linux/macOS с Bash

```bash
bash ./build.sh
```

Используется именно `bash ./build.sh`, поэтому executable bit файла `build.sh` после распаковки архива не требуется.

## Исходный архив

Каталог `dist` является результатом сборки и не должен включаться в архив исходного кода.

В source-пакет также не следует включать:

```text
dist/
__pycache__/
*.pyc
*.exe
```

Готовые Windows EXE и `SHA256SUMS.txt` распространяются отдельно как release artifacts.

## Безопасность

Приложение предназначено для локальной работы.

Основные ограничения:

- HTTP-сервер принимает только loopback-адреса;
- проверяются Host и Origin;
- cross-site API-запросы отклоняются;
- используются защитные HTTP-заголовки и Content Security Policy;
- удалённые JavaScript, CSS, шрифты и изображения для работы интерфейса не требуются;
- отсутствуют телеметрия, автоматический updater и удалённая загрузка игровых данных;
- API имеет ограничения методов, размера JSON и числа одновременных запросов;
- неизвестные и повторяющиеся JSON-поля отклоняются;
- пути пользовательских данных защищены от выхода за разрешённые каталоги и переходов через reparse/symlink-объекты;
- response cache, сессии, профиль и история имеют ограниченный размер;
- приложение поддерживает штатное завершение и освобождение локального listener.

## Структура

Основные компоненты:

- `server.go` — запуск приложения, локальный HTTP-сервер и middleware;
- `main.go` — игровые модели, загрузка данных, поиск и API;
- `lifecycle.go` — browser-сессии и завершение приложения;
- `storage.go` — пользовательский профиль, резервные копии и очистка;
- `cache.go` — ограниченный response cache;
- `web/` — локальный HTML, CSS и JavaScript;
- `assets/` — встроенные игровые данные и компактный projection содержимого сундуков;
- `resources/` — Windows manifest и иконка;
- `tools/` — тесты, smoke-проверки и вспомогательные инструменты.
