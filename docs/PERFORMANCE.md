# Производительность

Поисковый запрос подготавливается один раз на запрос API. Нормализованные названия для сортировки и поисковые документы рецептов создаются при загрузке базы и затем используются повторно. Сравнение подготовленных названий и поиск по документу не выделяют память. Порядок русских букв, включая «ё», правила регистра, фильтры и пагинация сохранены.

Для контроля используйте реальные обработчики каталога:

```powershell
$env:GOMAXPROCS = "1"
go test -run '^$' -bench '^BenchmarkCatalog' -benchmem -benchtime=1s -count=3 .
Remove-Item Env:\GOMAXPROCS
```

Загрузка данных исключена из измеряемого цикла. Ответ API, сортировка и сериализация включены. Сравнивайте версии на одном компьютере с одинаковым Go и параметрами запроса; отдельно измеряйте холодный запуск и память всего приложения.

## Контрольное сравнение 2.0.5 → 2.0.6

Общий стенд: Intel Xeon Platinum 8272CL 2,60 ГГц, Linux amd64, Go 1.26.6, `GOMAXPROCS=1`. Это измерение Go-обработчиков вне Windows; оно не измеряет отрисовку WebView2 или скорость на конкретном старом ПК.

| Запрос | 2.0.5, мс/операцию | 2.0.6, мс/операцию | 2.0.5, байт/операцию | 2.0.6, байт/операцию |
|---|---:|---:|---:|---:|
| Предметы, сортировка по имени, 24 записи | 505,70 | 134,11 | 25 038 189 | 518 525 |
| Предметы, поиск отсутствующего ID | 58,96 | 12,07 | 2 845 618 | 17 434 |

Контрольный прогон использовал `-benchmem -benchtime=300ms -count=1`; это отдельное сравнительное измерение, не статистическая гарантия. Выдача каталога ускорилась примерно в 3,8 раза, выделения памяти сократились на 97,9%. Поиск ускорился примерно в 4,9 раза. Эти байты — временные выделения на запрос, а не общий объём RAM процесса: подготовленные индексы занимают постоянную память.

114 ответов API по пяти каталогам, двум серверам, сортировкам и поисковым запросам совпали с исходной версией побайтно. Совпал также полный порядок названий. Регрессионные тесты проверяют русскую сортировку, поиск без повторной подготовки, переключение сервера и ограничение повторов сохранения профиля.

Таймер БГ приостанавливается в скрытом окне. Повторные ошибки записи профиля используют задержки 1, 2, 4, 8 и 16 секунд, затем требуют ручного повтора; постоянные ошибки запроса прекращают автоматические попытки сразу. Неподтверждённые изменения остаются видимыми пользователю.

Windows-сборки сохраняют уровни CPU `GOAMD64=v1`, `GO386=sse2` и `GOARM64=v8.0`. Эти параметры относятся к Go-коду; WebView2 предъявляет собственные требования к процессору и ОС. Отдельные сборки Windows 7/8/8.1 используют x64 или x86 и Runtime 109; для несовместимых CSS-цветов предусмотрены обычные объявления. Проверка на реальном старом ПК должна включать холодный запуск, поиск, быструю смену сервера, избранное, сворачивание и повторное открытие. Порядок и ограничения проверки: [WINDOWS_LEGACY.md](WINDOWS_LEGACY.md).
