# Отчёт о проверке Iris Online Database 1.1.0

Дата проверки: 12 августа 2026 года.

## Итог

Версия приложения повышена до **1.1.0**. Проведена полная вычитка пользовательских русских текстов в интерфейсе, сообщениях приложения и сопроводительных файлах. Исправлены орфография, пунктуация, грамматика, стилистика, технические кальки и несогласованность терминов.

Игровые исходные данные не редактировались.

## Основные изменения текста

- унифицированы названия разделов, фильтров, источников получения и элементов навигации;
- технические и неестественные формулировки заменены на понятные русские варианты без изменения смысла;
- пользовательские подписи характеристик приведены к единому стилю, где это не затрагивает игровые названия из базы;
- «Квест» как пользовательская категория источника заменён на «Задание»; внутренние значения источников в данных не менялись;
- пояснение различий между The Original и Iris Kiss Kiss упрощено;
- пояснение расчёта шанса выпадения переписано без внутренних терминов таблиц;
- сообщения запуска, ошибок и завершения приложения вычитаны и согласованы;
- README, документация в `docs/`, LICENSE и описание совместимости профиля вычитаны и обновлены для версии 1.1.0.

Игровые строки, которые поступают непосредственно из встроенной базы, намеренно не переписывались.

## Дополнительные изменения интерфейса

- в верхней части приложения постоянно отображаются версия и статус: «Актуальная», «Доступно …», «Проверка…» или «Статус неизвестен»;
- добавлена кнопка ручной проверки обновлений, которая выполняет новый запрос, а не использует кэш автоматической проверки;
- разбор номера версии допускает распространённые варианты записи вроде `1.1`, `1.1.`, `v1.1`, `v 1.1.0.` и нормализует их до семантической версии;
- названия серверов в пользовательском интерфейсе приведены строго к `The Original` и `Iris Kiss Kiss`;
- версия и статус обновления расположены в одной строке с основными разделами «Предметы», «Монстры» и «Рецепты»;
- блок «Последняя запись ВКонтакте» перенесён в самый низ главной страницы;
- приложение больше не обращается к VK напрямую: оно читает подготовленный файл `data/latest-vk.json` с GitHub;
- `.github/workflows/update-vk-news.yml` раз в час и вручную запускает Playwright, определяет последнюю запись публичной стены и обновляет JSON только при реальном изменении;
- при ошибке VK старый рабочий JSON не перезаписывается;
- кнопка «Проверить новую запись» принудительно перечитывает JSON с GitHub;
- при отсутствии интернета показывается локальная заставка, поэтому главная страница остаётся полноценной без сети;
- новая вёрстка проверена на ширинах 320, 375, 640 и 1280 px, элементы управления не создают горизонтального переполнения.

## Версия и Windows-ресурсы

- интерфейс: `1.1.0`;
- серверный маркер: `1.1.0`;
- сценарии сборки: `1.1.0`;
- Windows-манифест: `1.1.0.0`;
- имена диагностических EXE: `IrisOnlineDB-1.1.0-diagnostic-go1.23.2-Windows-*.exe`.

Требуемая версия Go для публикационной сборки остаётся **Go 1.26.5**, как указано в `.go-version`. В текущей среде доступны диагностические сборки на **Go 1.23.2**; они не должны выдаваться за официальный релиз, собранный требуемой версией Go.

## Проверки

Пройдены:

- `go test ./...`;
- `go test -race -count=1 ./...`;
- `go vet ./...`;
- `node --check web/app.js`;
- 89 из 89 Python unit-тестов;
- API smoke test;
- lifecycle smoke test;
- RSS smoke test;
- проверка архитектуры и диагностических маркеров Windows EXE;
- проверка Windows-ресурсов, манифеста и значков для x64, x86 и ARM64; `.syso` генерируются сборкой и не хранятся в репозитории;
- проверка воспроизводимости Windows EXE: две последовательные сборки из одного состояния совпали побайтно;
- `header_news_smoke_test.py`: версия/статус находятся в одной строке с основными разделами, блок ВКонтакте является последним блоком главной, онлайн- и офлайн-состояния корректны; проверены ширины 320, 375, 640 и 1280 px без горизонтального переполнения.

Полный `ui_smoke_test.py` в текущей Linux/container-среде пройден с доступным системным Chromium. API, lifecycle, RSS и focused header/news smoke-тесты также были успешно выполнены по отдельности. Единый длительный запуск всего smoke-набора в одном вызове внешней audit-среды не удалось наблюдать до завершения из-за лимита выполнения самой среды; отдельные PASS не заменяют этот невыполненный интегральный прогон.

## Исправления по итогам release-аудита

- исправлена потеря безопасных неизвестных полей профиля, если перед ними встречался неизвестный ключ длиннее допустимого лимита; добавлен regression-тест;
- `repository_audit.py` теперь обнаруживает запрещённые каталоги и артефакты исходного архива, включая `__pycache__`, `.ruff_cache`, `dist` и `$coverage`;
- `psutil` добавлен в зафиксированные Python-зависимости smoke/audit-набора, а Dependabot расширен на Python-зависимости;
- локальный `run_all_checks.sh` использует фактическую версию Go в диагностическом маркере и дополнительно проверяет чистоту source tree, форматирование, модульную целостность и сборку без оставления бинарника в репозитории;
- CI пишет временный build-output и Python bytecode в `$RUNNER_TEMP`, поэтому собственные проверки чистоты исходников не ломаются из-за артефактов, созданных предыдущими шагами CI;
- исправлена документация по генерации `.syso`, источнику новости VK и зависимостям smoke-тестов.
